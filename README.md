# E-Kratong

ระบบลอยกระทงออนไลน์ **เพื่อลดขยะในแม่น้ำ** เล่าห้าตำนานผ่านกระทงห้าแบบ ลอยในสายน้ำเดียวกับทุกคน (เห็นกระทงของกันและกันภายในไม่กี่วินาที) ปล่อยโคม ลอยทุกข์ และให้คำมั่นดูแลแม่น้ำ

หลังคืนลอยกระทง 2568 กรุงเทพมหานครเก็บกระทงขึ้นจากแม่น้ำและคูคลองได้ 391,027 ใบภายในคืนเดียว เป็นวัสดุธรรมชาติ 82.76% ขนมปัง 10.01% และโฟม 7.23% ซึ่งต้องนำไปฝังกลบ ([ไทยรัฐออนไลน์](https://www.thairath.co.th/news/local/bangkok/2893694), [PPTV](https://www.pptvhd36.com/news/%E0%B8%AA%E0%B8%B1%E0%B8%87%E0%B8%84%E0%B8%A1/260859)) E-Kratong ให้ลอยได้เหมือนเดิมโดยไม่มีขยะลงน้ำสักชิ้น

เวอร์ชันนี้มีเซิร์ฟเวอร์ของตัวเอง ไม่ต้องติดตั้งแพ็กเกจเพิ่ม (zero dependencies) ใช้แค่ Node.js

## เริ่มใช้งาน

ต้องใช้ Node.js 22.13 ขึ้นไป (มี SQLite ในตัว)

```bash
npm start
```

แล้วเปิด http://localhost:3000

ระหว่างพัฒนา ใช้คำสั่งนี้ให้เซิร์ฟเวอร์รีสตาร์ตเองเมื่อแก้ `server.js` (ส่วน `index.html` เซิร์ฟเวอร์โหลดใหม่ให้อัตโนมัติอยู่แล้ว)

```bash
npm run dev
```

## ใช้ในงานลอยกระทง (โหมดจอใหญ่)

1. ต่อคอมพิวเตอร์ที่รันเซิร์ฟเวอร์เข้า Wi-Fi เดียวกับคนในงาน แล้วรัน `npm start`
2. เปิด http://localhost:3000/#screen บนเครื่องที่ต่อโปรเจกเตอร์ (หรือกดไอคอนจอที่มุมขวาบน) แล้วกด "เต็มจอ"
3. คนในงานสแกน QR ที่มุมขวาล่าง ลอยกระทงจากมือถือ กระทงจะไหลเข้าจอ และคำอธิษฐานขึ้นตัวใหญ่ทีละใบ

ในโหมดจอใหญ่:

- **QR code** จอใหญ่โหลดตัวสร้าง QR จากเครื่องจัดงาน จึงสแกนเข้าเว็บผ่าน Wi-Fi ภายในได้แม้ออกอินเทอร์เน็ตไม่ได้ ระบบหาที่อยู่เครื่องให้เอง เช่น `http://192.168.1.20:3000/` ผู้จัดแก้ได้ด้วย `PUBLIC_URL` หรือปุ่ม "แก้ลิงก์" ใต้ QR
- **ปล่อยโคมพร้อมกัน** ทุกจอปล่อยโคมพร้อมกันตามเวลาใน `MOMENTS` (ค่าเริ่มต้น 19:00, 20:00, 21:00, 22:00 เวลาไทย) นับถอยหลัง 10 วินาทีก่อนปล่อย
- **พิธีกรกดนับถอยหลังเองได้** ตั้ง `ADMIN_TOKEN` แล้วใส่รหัสในเบราว์เซอร์ของเครื่องฉาย (ดูหัวข้อดูแลเนื้อหา) จะมีปุ่ม "นับถอยหลังปล่อยโคมเดี๋ยวนี้" ทุกจอและทุกมือถือจะนับ 15 วินาทีพร้อมกัน
- หน้าจอไม่ดับเองระหว่างฉาย (ถ้าเบราว์เซอร์รองรับ) กด Esc เพื่อออก

ฟีเจอร์อื่นในชุดนี้:

- **ส่งพร** แตะกระทงของคนอื่นแล้วกด "ส่งพร" กระทงจะมีประกายและเรืองแสงกว้างขึ้นตามจำนวนพรที่ได้รับ ทุกคนเห็นพร้อมกัน (1 คนส่งได้ 1 ครั้งต่อกระทง และส่งให้กระทงตัวเองไม่ได้)
- **ตัวอย่างคำอธิษฐาน** แตะเพื่อใช้ได้เลย เปลี่ยนตามแบบกระทงที่เลือก
- **ประหยัดแบต** เปิดจาก **ตั้งค่า → ประหยัดแบต** เพื่อจำกัดภาพเคลื่อนไหวที่ 30 เฟรมต่อวินาทีและลดความละเอียด ระบบจำค่าไว้บนเครื่อง ทั้งสองโหมดพักการวาดเมื่อเลื่อนพ้นแม่น้ำและภาพตัวอย่าง หรือเมื่อซ่อนแท็บ
- **กรองคำหยาบ** ทั้งในหน้าเว็บและที่เซิร์ฟเวอร์ ตรวจเป็นคำและคู่คำ จึงไม่บล็อกคำปกติอย่าง "หีบ", "สัดส่วน", "แกงกะหรี่", "ดอกทองอุไร" แก้รายการคำได้ที่ `BAD_WORDS` / `BAD_PAIRS` ใน `server.js` และ `index.html` (ให้ตรงกันทั้งสองไฟล์)
- **แจ้งว่าไม่เหมาะสม** กระทงจะหายจากจอคนที่แจ้งทันที และถ้ามีคนแจ้งจากเครือข่ายต่างกันครบ `REPORT_HIDE` คน (ค่าเริ่มต้น 3) กระทงจะถูกซ่อนจากทุกจอ ผู้ดูแลยังลบเองได้ตลอด

## โต๊ะทำกระทง (ทำกระทงร่วมกันบนแผนที่ไทย)

เปิดที่ `/workshop.html` (หน้าหลักมีปุ่ม "ทำกระทงกับเพื่อน บนแผนที่ไทย" เมื่อใช้งานผ่านเซิร์ฟเวอร์นี้)

1. เลือกจุดลอยบนแผนที่ประเทศไทย (สายน้ำที่ตั้งไว้ 8 แห่ง หรือแตะปักเอง ปักได้เฉพาะในประเทศไทย ตรวจทั้งหน้าเว็บและเซิร์ฟเวอร์) แล้วกด "ตั้งโต๊ะทำกระทง"
2. คัดลอกลิงก์ชวนเพื่อน ใครเปิดลิงก์ก็เข้าโต๊ะเดียวกัน เห็นชิ้นงานที่วางและย้ายพร้อมกัน
3. วางวัสดุจากถาด (ฐานต้นกล้วย ใบตอง กลีบพับ กลีบบัว ดาวเรือง เทียน) ลากย้าย หมุน ย่อขยาย สลับชั้น ลบ และ **ตัดรูปทรง** (กดปุ่มแล้วลากวนรอบส่วนที่อยากเก็บ)
4. **สติกเกอร์จากเครื่องแต่ละคน**: กด "เพิ่มสติกเกอร์จากเครื่อง" เลือกรูป PNG, JPG หรือ WebP เบราว์เซอร์จะย่อรูปให้ไม่เกิน 192 พิกเซลก่อนส่ง รูปของใครเครื่องใครก็ไม่เหมือนกัน แต่ทุกคนในโต๊ะเห็นเหมือนกัน
5. กด "นำไปลอย" ใส่คำอธิษฐานและชื่อผู้ร่วมทำ เลือกจุดลอย กระทงจะขึ้นบนแผนที่ และลอยในสายน้ำหลักด้วยรูปของตัวเอง โต๊ะนั้นจะล็อก แก้ต่อไม่ได้

ข้อจำกัดและความปลอดภัย (ฝั่งเซิร์ฟเวอร์ตรวจทั้งหมด ไม่ไว้ใจหน้าเว็บ): โต๊ะละไม่เกิน 64 ชิ้น สติกเกอร์ไม่เกิน 20 รูปหรือ 2 MB ต่อโต๊ะ รับเฉพาะไฟล์ PNG จริง ตรวจหัวไฟล์และขนาด คำอธิษฐานและชื่อผ่านตัวกรองคำหยาบ จำกัดความถี่ต่อคนและต่อ IP โต๊ะที่ไม่มีใครแตะ 48 ชั่วโมงถูกลบพร้อมสติกเกอร์ และสติกเกอร์ที่แปะบนกระทงที่ลอยแล้วไม่ถูกเปิดสู่สาธารณะ มีแต่รูปกระทงสำเร็จที่ลอยแล้ว

การทำงานร่วมกัน: ทุกการแก้ไขเป็นคำสั่งเล็ก ๆ (`ops`) ที่เซิร์ฟเวอร์ตรวจแล้วส่งสถานะโต๊ะให้ทุกคนผ่านการเชื่อมต่อของโต๊ะนั้น (Server-Sent Events เฉพาะในโต๊ะ ไม่เกี่ยวกับสายน้ำหลัก) ถ้าสองคนแก้ชิ้นเดียวกันพร้อมกัน คนที่ช้ากว่าจะได้ค่าล่าสุดและมีข้อความแจ้ง ภาพวาดและการตัดทั้งหมดทำบนเครื่องผู้ใช้ เซิร์ฟเวอร์เก็บแค่ตำแหน่งและรหัสรูป

### แผนที่จริงบนหน้าโต๊ะทำกระทง

หน้าแผนที่เป็นฉากกลางคืนเหมือนหน้าหลัก (ดวงจันทร์ ดาว ตัวเลข "ลอยแล้ว ... ใบ" ปุ่ม "สร้างกระทง") และใช้แผนที่จริง: ถนน แม่น้ำ คลอง ซูมและหมุนได้ เมื่อเลือกสายน้ำ กล้องจะบินเข้าไปและเอียงเป็นมุม 3 มิติ กระทงที่ลอยแล้วแสดงเป็นรูปจริงของกระทงบนแผนที่ (40 ใบล่าสุดเป็นรูป ที่เหลือเป็นจุด) แตะแผนที่เพื่อปักจุดลอยเองได้ ในประเทศไทยเท่านั้น

- **ไลบรารีและข้อมูล:** [MapLibre GL JS](https://maplibre.org/) 6.17.0 (ใบอนุญาต BSD-3 เก็บไว้ที่ `assets/maplibre-LICENSE.txt`) อยู่ในโปรเจกต์ ไม่โหลดจาก CDN ไทล์แผนที่สไตล์ dark มาจาก [OpenFreeMap](https://openfreemap.org/) ข้อมูล © OpenStreetMap contributors ใช้ฟรีไม่ต้องมีคีย์ เครดิตแสดงที่มุมล่างของแผนที่ ห้ามถอดออก
- **ความเป็นส่วนตัว:** เบราว์เซอร์ของผู้ใช้จะเรียก `tiles.openfreemap.org` โดยตรงเพื่อโหลดไทล์ ผู้ให้บริการจึงเห็น IP และตำแหน่งที่ดูบนแผนที่ (ไม่ผ่านเซิร์ฟเวอร์ของเรา) ถ้าไม่ต้องการ ให้ใช้ `workshop.html?map=svg`
- **ทางสำรอง:** ถ้าโหลดแผนที่จริงไม่ได้ (ออฟไลน์ ไม่มี WebGL หรือบริการล่ม) หน้าเว็บกลับไปใช้แผนที่ประเทศไทยแบบ SVG เดิมเองภายใน 12 วินาที ใช้งานได้ครบ เพียงไม่มีถนนและแม่น้ำ
- **ข้อจำกัด:** OpenFreeMap เป็นบริการสาธารณะฟรีที่ไม่มีข้อตกลงรับประกันระดับบริการ ถ้างานมีคนใช้หนักมาก ควรติดตั้งไทล์ของตัวเองหรือสมัครบริการแผนที่แบบเสียเงิน (แก้ที่ค่า `STYLE` ใน `assets/workshop-realmap.mjs`) และถ้านำไปใช้บน Vercel ต้องคงค่า CSP ใน `vercel.json` ที่อนุญาต `tiles.openfreemap.org`
- **ขนาด:** ไฟล์ MapLibre รวมประมาณ 1.7 MB (โหลดครั้งแรกครั้งเดียวต่อเบราว์เซอร์ แล้วเบราว์เซอร์ตรวจกับเซิร์ฟเวอร์ด้วย ETag)

ที่มาของเส้นขอบประเทศ: [Natural Earth](https://www.naturalearthdata.com/) (สาธารณสมบัติ) ลดจุดให้เหลือไม่กี่ร้อยจุดใน `assets/thailand-outline.json` ใช้เส้นขอบนี้ตรวจว่าจุดที่เลือกอยู่ในประเทศไทย (ขอบหยาบกว่าความจริง จุดริมชายแดนหรือชายฝั่งอาจถูกปฏิเสธทั้งที่อยู่ในไทย ผมย้ายจุดทะเลสาบสงขลาที่ตั้งไว้เดิมเข้ามาในขอบเพราะตกขอบ)

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเว็บและโหมดในเครื่อง ใช้ได้ทั้งกับเซิร์ฟเวอร์นี้ บน claude.ai และเปิดจากไฟล์ |
| `server.js` | เซิร์ฟเวอร์: ตรวจและบันทึกการเขียน, เขียนบันทึกเหตุการณ์ (event log), ฐานข้อมูล, จำกัดความถี่ |
| `data/log/` | บันทึกเหตุการณ์ที่เซิร์ฟเวอร์เขียนให้หน้าเว็บอ่าน (สร้างให้เอง ลบและสร้างใหม่ทุกครั้งที่เปิดเซิร์ฟเวอร์) |
| `assets/moon.jpg` | ภาพถ่ายดวงจันทร์เต็มดวงที่ใช้วาดบนฟ้า |
| `assets/river-log.mjs` | ตัวอ่านรายการสรุปและเหตุการณ์สำหรับสายน้ำร่วม |
| `assets/qrcode-1.4.4.js` | ตัวสร้าง QR ที่โหลดเมื่อเปิดจอใหญ่ ลิขสิทธิ์และเงื่อนไขอยู่ใน `assets/qrcode-LICENSE.txt` |
| `assets/ramwong-loy-krathong.mp3` | เพลง “รำวงลอยกระทง” เพลงประกอบหน้าเว็บ (เปิดอัตโนมัติเมื่อเข้าเว็บครั้งแรก) |
| `music/` | โฟลเดอร์สำหรับผู้จัดที่ต้องการใช้เพลงอื่นเป็นเพลงของงาน |
| `data/e-kratong.db` | ฐานข้อมูล SQLite (สร้างให้อัตโนมัติ) |
| `scripts/load-test.js` | สคริปต์ทดสอบรับโหลด |
| `Dockerfile` | สำหรับ deploy ด้วย Docker |

## เพลง

เพลงประกอบคือ **รำวงลอยกระทง** (`assets/ramwong-loy-krathong.mp3`) วนซ้ำเมื่อจบ

**เปิดอัตโนมัติ:** เมื่อเข้าเว็บครั้งแรก หน้าเว็บจะพยายามเปิดเพลงเอง เบราว์เซอร์ส่วนใหญ่ (โดยเฉพาะมือถือ) ไม่อนุญาตให้เล่นเสียงก่อนผู้ใช้แตะหน้าจอ ในกรณีนั้นเพลงจะเริ่มเมื่อผู้ใช้แตะหรือกดแป้นครั้งแรก ถ้าผู้ใช้กด **พักเพลง** ระบบจะจำค่านั้นไว้ในเครื่อง (`localStorage` คีย์ `e-kratong.music`) และไม่เปิดเองอีกในครั้งต่อไป กด **เปิดเพลง** อีกครั้งเพื่อกลับมาเปิดอัตโนมัติ

**ที่มาและลิขสิทธิ์ของไฟล์เพลง:** `assets/ramwong-loy-krathong.mp3` เป็นไฟล์ที่เจ้าของโปรเจกต์นำมาใส่เอง ผมไม่ได้ตรวจว่าเป็นการบันทึกเสียงของใครหรือมีเงื่อนไขการใช้งานอย่างไร เพลงรำวงลอยกระทงต้นฉบับและการบันทึกเสียงอาจยังมีลิขสิทธิ์ ผู้เผยแพร่เว็บต้องตรวจสิทธิ์เองก่อนเปิดใช้งานสาธารณะหรือเชิงพาณิชย์ ส่วน `assets/loy-krathong-2026.mp3` เป็นเพลงที่แต่งด้วย AI ตามที่เจ้าของโปรเจกต์ระบุ (ไม่ได้ใช้เป็นค่าเริ่มต้นแล้ว)

เบราว์เซอร์เริ่มโหลด MP3 จากไฟล์ของเว็บเมื่อผู้ฟังกดเปิด จึงเปิดเพลงผ่าน Wi-Fi ภายในงานได้ หากนำเฉพาะ `index.html` ไปใช้เดี่ยว ๆ ให้กด **ตั้งค่า → เลือกไฟล์เพลงจากเครื่องนี้** แล้วเลือก `ramwong-loy-krathong.mp3`

- **เปลี่ยนเพลงให้ทั้งงาน** โดยวางไฟล์เพลงใน `music/` หรือตั้งค่า `MUSIC_FILE` รองรับ MP3, M4A, AAC, OGG, WAV และ FLAC ตามที่เบราว์เซอร์ของผู้ฟังเล่นได้
- **เปลี่ยนเพลงเฉพาะเครื่อง** โดยกด **ตั้งค่า → เลือกไฟล์เพลงจากเครื่องนี้** ไฟล์จะเล่นในเบราว์เซอร์ของผู้เลือก กด **กลับไปใช้เพลงของงาน** เพื่อสลับกลับ

## เด็กลงน้ำเก็บกระทง

ทุกครั้งที่หน้าแม่น้ำมีกระทงตั้งแต่ 3 ใบขึ้นไป จะมีเด็กลุยน้ำเข้ามาจากฝั่งท้ายน้ำ (ด้านขวา) ก้มเก็บกระทงที่ลอยผ่าน ยกขึ้นเหนือหัว แล้วเดินออกไป (จอกว้างเกิน 900 px มีได้ 2 คนพร้อมกัน) ลอยกลับมาใหม่หลังประมาณ 14 วินาที

- เป็นภาพเคลื่อนไหวบนเครื่องผู้ชมเท่านั้น **ไม่เขียนหรือลบข้อมูลใด ๆ** บนเซิร์ฟเวอร์ ไม่กระทบกระทงหรือจำนวนที่คนอื่นเห็น
- ไม่เก็บกระทงของผู้ชมเอง กระทงที่กำลังเปิดอ่าน และกระทงที่เพิ่งลอยเข้ามาไม่ถึง 4 วินาที
- ปิดได้ที่ **ตั้งค่า → เด็กลงน้ำเก็บกระทง** (จำค่าไว้ในเครื่อง คีย์ `e-kratong.kids`) และจะไม่แสดงเมื่อผู้ใช้ตั้งค่าลดการเคลื่อนไหวของระบบ

| ประกอบ "สายน้ำ" จากบันทึกเหตุการณ์: เรียงใหม่สุดก่อน คนละไม่เกิน 3 ใบ ภายใน 48 ชม. | ตรวจสิทธิ์: ลบได้เฉพาะของตัวเองหรือผู้ดูแล, ส่งพรได้ครั้งเดียวต่อคน |
| นับพร ตรวจว่ามีกระทงใหม่เข้ามา แล้วให้กระทงลอยเข้าฉาก | เก็บลงฐานข้อมูล แล้วต่อท้ายบันทึกเหตุการณ์ |
| นับถอยหลังปล่อยโคมพร้อมกัน (คำนวณจากเวลา ไม่ต้องถามเซิร์ฟเวอร์) | เขียนไฟล์ติดตามความคืบหน้า `head.json` |
| เล่นเพลงลอยกระทง สร้างการ์ดภาพ | |

### บันทึกเหตุการณ์ (event log) แทนการเชื่อมต่อค้างไว้

เซิร์ฟเวอร์ไม่ได้ส่งข้อมูลให้ทีละคน และไม่ถือการเชื่อมต่อของใครไว้เลย แต่เขียนไฟล์ให้หน้าเว็บมาอ่านเอง

1. ทุกการเปลี่ยนแปลงที่ตรวจผ่านแล้ว (กระทงใหม่ กระทงถูกลบ พรใหม่) ถูกพักไว้ แล้วปิดเป็นไฟล์ `seg-…json` ทุก 1 วินาที ไฟล์นี้ไม่ถูกแก้ไขอีกเลย
2. ทุก 15 วินาที (หรือเมื่อครบ 8 ไฟล์) เซิร์ฟเวอร์เขียน `cp-…json` เก็บสายน้ำทั้งหมด ณ ตอนนั้น คนที่เพิ่งเปิดหน้าเว็บโหลดไฟล์นี้ไฟล์เดียวก็ได้สายน้ำครบ
3. ไฟล์ `head.json` (ไม่กี่ร้อยไบต์) บอกว่าไฟล์ล่าสุดคือไฟล์ไหน หน้าเว็บอ่านทุก 2.5 วินาที และถ้าไม่มีอะไรเปลี่ยน เซิร์ฟเวอร์ตอบ 304 สั้น ๆ
4. แท็บที่เปิดอยู่ตามไฟล์เหตุการณ์ข้ามจุดสร้างรายการสรุปได้ เมื่อชุดใดมีข้อมูลตกหล่น เซิร์ฟเวอร์ทำเครื่องหมาย `incomplete` และระบุใน `repairThrough` เมื่อรายการสรุปครอบคลุมชุดนั้น แท็บจะโหลดรายการสรุปเพื่อเติมให้ครบแม้จะอ่านไฟล์เหตุการณ์ถึงลำดับเดียวกันแล้ว ถ้าพักนานเกินช่วงที่ระบุใน `replayAfter` แท็บจะเริ่มจากรายการสรุปล่าสุด

เพราะไฟล์ `seg` และ `cp` ไม่เปลี่ยนเลย จึงแคชได้ตลอดกาล (`immutable`) และให้ nginx หรือ CDN ส่งแทน Node ได้ทั้งหมด ดูหัวข้อ "หลัง nginx"

ข้อแลกเปลี่ยน: กระทงของคนอื่นเข้าจอช้ากว่าแบบเชื่อมต่อค้างไว้เล็กน้อย (วัดจริงได้ราว 1.3 วินาที สูงสุดราว 3.5 วินาที) ซึ่งไม่กระทบการลอยของตัวเอง เพราะกระทงของตัวเองลอยลงจอทันทีโดยไม่รอเซิร์ฟเวอร์

## ทำไมกระทงเยอะแล้วไม่กระตุก

หลักคือ **ทุกอย่างที่ใช้แรมต้องมีเพดาน** ไม่ว่ากระทงในระบบจะมีกี่ใบ

| ส่วน | ทำอย่างไร |
|---|---|
| เก็บข้อมูล | อยู่ใน SQLite (โหมด WAL) ไม่ได้เก็บเป็น array ในแรม |
| ในแรม | เก็บสายน้ำ 300 ใบล่าสุด คนละไม่เกิน 3 ใบ เมื่อต้องสร้างใหม่ SQLite อ่านตามดัชนีเวลาจากใหม่ไปเก่าและหยุดทันทีที่ได้ครบ |
| อายุกระทง | ลอยอยู่ 48 ชั่วโมงแล้วไหลไป ระบบลบทุก 1 นาที |
| ต่อคน | เก็บได้ไม่เกิน 12 ใบในช่วง 48 ชม. ใบเก่าสุดไหลไปเอง |
| หน้าแรกและไฟล์บันทึก | สร้างครั้งเดียว บีบอัด gzip ไว้ล่วงหน้า ส่งซ้ำได้โดยไม่ต้องประมวลผลใหม่ |
| ไฟล์ไม่โตตามจำนวนคน | แต่ละไฟล์ `seg` รวบการเปลี่ยนแปลงในวินาทีนั้น เก็บกระทงใหม่ไม่เกิน 25 ใบ (ที่เหลือเก็บลงฐานข้อมูลและไปอยู่ในไฟล์ `cp` ถัดไป) กระทงที่ถูกลบในวินาทีเดียวกันไม่ถูกส่ง และพรเก็บเฉพาะค่าล่าสุด |
| ไม่มีการเชื่อมต่อค้างไว้ | ไม่มีใครถือการเชื่อมต่อกับเซิร์ฟเวอร์ จึงไม่มีเพดานจำนวนผู้ชม และไม่มีคนเน็ตช้าที่ทำให้ข้อมูลค้างในแรม |
| ตัวนับ | นับในแรมแล้วนับใหม่จากฐานข้อมูลเป็นระยะ ไม่ `COUNT(*)` ทุกคำขอ |
| กันสแปม | ผู้ใช้ลอยได้ 3 ใบติดกัน แล้วเพิ่ม 1 ใบต่อ 10 วินาที แต่ละ IP เริ่มได้ 30 ใบและเพิ่ม 1 ใบต่อวินาที คำอธิษฐานยาวได้ 140 กลุ่มตัวอักษร ชื่อ 24 กลุ่ม คำขอลอยกระทงรับได้ 16 KiB เพื่อรองรับสระ วรรณยุกต์ และอีโมจิ ส่วนคำขอ JSON อื่นรับได้ 4 KiB |
| ฝั่งหน้าเว็บ | วาดกระทงบนจอพร้อมกันไม่เกิน ~58 ใบ (มือถือ ~17) ใบที่ไหลออกขอบจอจะสลับให้ใบถัดไปในคิว, วาดตัวกระทงครั้งเดียวแล้วแคชเป็นภาพ, เครื่องช้าจะลดจำนวนเอง |

ผลทดสอบเดิมบนเครื่องพัฒนาก่อนเพิ่มโหมดประหยัดแบต ใช้ Windows และ Node 22 โดยรันทั้งเซิร์ฟเวอร์และตัวยิงโหลดบนเครื่องเดียวกัน

แบบจำลองผู้ชม 2,000 คนที่อ่านบันทึกทุก 2.5 วินาทีเหมือนหน้าเว็บจริง (ผู้ชม 2,000 คนทำให้เกิดคำขออ่านราว 800 ถึง 1,100 ครั้งต่อวินาที) เป็นเวลา 20 วินาที:

| สถานการณ์ | CPU ของเซิร์ฟเวอร์ | แรม | ข้อมูลที่ผู้ชมแต่ละคนโหลด |
|---|---|---|---|
| ไม่มีใครลอย | 6.8% ของแกนเดียว | 77 MB | 9 KB |
| ลอยกระทง 5,000 ใบพร้อมกัน (1,645 ใบ/วินาที, p99 63 ms) | 20.2% ของแกนเดียว | 76 MB | 5 KB |

- ฝั่งหน้าเว็บ: ขณะมีกระทงเข้า 1,500 ใบรัว ๆ จอใหญ่ยังลื่นที่ 165 เฟรมต่อวินาที เท่ากับตอนว่าง และตัวนับขึ้นครบ 1,500
- กระทงในฐานข้อมูลเพิ่มจาก 30,000 → 50,000 → 70,000 ใบ (ทดสอบกับเวอร์ชันก่อนใช้บันทึกเหตุการณ์): heap ที่ใช้จริงหลัง GC อยู่ที่ 5 → 6 → 6 MB (คงที่)
- ตัวยิงโหลดกับเซิร์ฟเวอร์รันบนเครื่องเดียวกัน ตัวเลขเวลาตอบจึงมากกว่าจริงเล็กน้อย แต่ CPU ที่วัดเป็นของโปรเซสเซิร์ฟเวอร์อย่างเดียว
- ยังไม่ได้ทดสอบ nginx หรือ CDN ส่งไฟล์บันทึกแทน Node (ดูหัวข้อ "หลัง nginx")

## ดูแลเนื้อหา (ลบกระทงที่ไม่เหมาะสม)

1. รันเซิร์ฟเวอร์พร้อม `ADMIN_TOKEN`
2. เปิดหน้าเว็บ กด F12 แล้วพิมพ์ในแท็บ Console:
   ```js
   localStorage.setItem('e-kratong.admin', 'รหัสที่ตั้งไว้')
   ```
3. รีเฟรชหน้า แตะกระทงใบไหนก็จะมีปุ่ม "นำออกจากสายน้ำ"

หรือลบผ่านคำสั่ง (เอา `k` ของกระทงจาก `/api/krathongs`):

```bash
curl -X DELETE -H "X-Admin-Token: รหัสที่ตั้งไว้" http://localhost:3000/api/krathongs/KEY
```

คนทั่วไปลบได้เฉพาะกระทงของตัวเอง ระบบจำเจ้าของด้วยรหัสสุ่มในเบราว์เซอร์ (ฝั่งเซิร์ฟเวอร์เก็บแค่ค่า hash ไม่เก็บรหัสจริง)

- ข้อความ "ลอยทุกข์" ไม่ถูกส่งไปเซิร์ฟเวอร์เลย
- คำอธิษฐานที่ปิดการแชร์ เซิร์ฟเวอร์ไม่เก็บข้อความ
- ไม่มีการเก็บอีเมล ชื่อจริง หรือ IP ลงฐานข้อมูล IP ใช้จำกัดความถี่ในแรมแล้วล้างทิ้งใน 10 นาที ส่วนการแจ้งไม่เหมาะสมเก็บแค่ค่า hash ของ IP ที่ใส่เกลือแบบสุ่มใหม่ทุกครั้งที่เปิดเซิร์ฟเวอร์ (ย้อนกลับเป็น IP ไม่ได้) และลบทิ้งตามอายุกระทง

## ทดสอบรับโหลด

รัน `npm test` เพื่อตรวจว่าผู้ชมได้รับกระทงครบหลังลอยพร้อมกัน 30 ใบ การตามเฉพาะเหตุการณ์ข้ามรายการสรุป การเติมกระทงหลังลบ และการเก็บข้อความภาษาไทย เทสต์ใช้ฐานข้อมูลชั่วคราวของตัวเอง

```bash
# หน้าต่างที่ 1: ปิดการจำกัดความถี่ชั่วคราว (ตัวยิงโหลดมาจาก IP เดียว)
HOST=127.0.0.1 DB_FILE=data/test-load/e-kratong.db RATE_LIMIT=off npm start

# หน้าต่างที่ 2
npm run load-test -- --viewers 1000 --posts 5000 --concurrency 50
```

บน PowerShell ใช้ `$env:HOST='127.0.0.1'; $env:DB_FILE='data/test-load/e-kratong.db'; $env:RATE_LIMIT='off'; npm start` ในหน้าต่างสำหรับทดสอบ

ดูสถานะเซิร์ฟเวอร์ได้ที่ http://localhost:3000/healthz (จำนวนคนที่เชื่อมต่อ, กระทงในช่วงเวลา, แรมที่ใช้)

## Deploy

### Docker

```bash
docker build -t e-kratong .
docker run -d --name e-kratong -p 3000:3000 -v e-kratong-data:/data -e ADMIN_TOKEN=รหัส e-kratong
```

### หลัง nginx (แนะนำเมื่อขึ้นโดเมนจริงพร้อม HTTPS)

ตั้ง `TRUST_PROXY=1` ที่เซิร์ฟเวอร์ และให้ nginx ส่งไฟล์บันทึกใน `data/log/` เองโดยไม่ผ่าน Node (ตั้ง `ONLINE_COUNT=off` ด้วย เพราะ Node จะไม่เห็นการอ่านของผู้ชมอีก) **ตัวอย่างนี้ยังไม่ได้ทดสอบกับ nginx จริง** ปรับพาธให้ตรงกับเครื่อง

```nginx
location = /log/head.json {
    alias /app/data/log/head.json;
    default_type application/json;
    add_header Cache-Control "public, max-age=2";
    gzip on; gzip_types application/json;
}
location ~ ^/log/((seg|cp)-[a-z0-9]+-[0-9]+\.json)$ {
    alias /app/data/log/$1;
    default_type application/json;
    gzip_static on;   # เซิร์ฟเวอร์เขียนไฟล์ .gz คู่กันไว้ให้แล้ว
    add_header Cache-Control "public, max-age=31536000, immutable";
}
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

### Deploy บน Vercel (หน้าเว็บบน Vercel + เซิร์ฟเวอร์ของเราไปรันที่อื่น)

**ทำไมเอาทั้งหมดขึ้น Vercel ตรง ๆ ไม่ได้:** เซิร์ฟเวอร์นี้ต้องเปิดค้างไว้ เก็บข้อมูลในไฟล์ SQLite บนดิสก์ถาวร และถือสถานะไว้ในหน่วยความจำ ส่วน Vercel รันเป็นฟังก์ชันที่ดับหลังตอบคำขอและไม่มีดิสก์ถาวร ข้อมูลจะหาย และโต๊ะทำกระทงร่วมกันจะไม่ทำงาน

วิธีที่ใช้: Vercel เสิร์ฟเฉพาะหน้าเว็บ (ไฟล์ใน `public/`) แล้วส่งต่อ `/api`, `/log`, `/music` ไปยังเซิร์ฟเวอร์ของเรา ผู้ใช้เห็นเป็นโดเมนเดียว ไม่ต้องตั้ง CORS

1. **รันเซิร์ฟเวอร์ของเราที่ที่เปิดค้างได้และมีดิสก์ถาวร** (เช่น Render, Railway, Fly.io หรือ VPS) ใช้ `Dockerfile` ในโปรเจกต์ได้เลย ต่อดิสก์ถาวรที่ `/data` และตั้งค่า
   - `TRUST_PROXY=1` (อ่าน IP ผู้ใช้จริงจาก Vercel)
   - `PUBLIC_URL=https://โดเมนบน-Vercel-ของคุณ/` (ลิงก์ใน QR ของจอใหญ่)
   - `ADMIN_TOKEN=รหัสยาว ๆ ที่เดายาก`
   - `ONLINE_COUNT=off` (Vercel แคช `head.json` ไว้สั้น ๆ เซิร์ฟเวอร์จึงนับคนออนไลน์ไม่ได้)
   - เช็กที่ `https://ที่อยู่เซิร์ฟเวอร์/healthz` ว่าตอบ `ok`
2. **ใส่ที่อยู่เซิร์ฟเวอร์ใน `vercel.json`** แทนที่ `YOUR-BACKEND.example.com` ทั้ง 3 จุดด้วยที่อยู่จริง (ไม่ต้องมี `https://` ซ้ำ และไม่ต้องมี `/` ท้าย) ถ้ายังไม่แทนที่ สคริปต์สร้างหน้าเว็บจะหยุดและบอกให้แก้
3. **Deploy** ด้วยบัญชี Vercel ของคุณเอง (ผมล็อกอินแทนไม่ได้)
   - ผ่านเว็บ: ใส่โปรเจกต์นี้ไว้บน GitHub แล้ว Import ใน Vercel ทีม `dry12` ระบบอ่าน `vercel.json` เองและรัน `node scripts/build-static.mjs`
   - หรือผ่านคำสั่ง: `npx vercel` แล้ว `npx vercel --prod`
4. เปิดหน้าที่ได้ แล้วลองลอยกระทงหนึ่งใบ และเปิดโต๊ะทำกระทง

ข้อควรรู้ (ยังไม่ได้ทดสอบบน Vercel จริง): สายน้ำหลักอ่านไฟล์บันทึกธรรมดา ผ่านการส่งต่อได้และ Vercel ช่วยแคชไฟล์ให้ด้วย แต่โต๊ะทำกระทงใช้การเชื่อมต่อค้าง (Server-Sent Events) ซึ่ง Vercel อาจตัดการเชื่อมต่อที่เปิดนาน ๆ หน้าเว็บจะเชื่อมใหม่เองภายใน 3 วินาทีและได้สถานะล่าสุดของโต๊ะ จึงควรเห็นแค่การกระตุกสั้น ๆ ถ้าเจอปัญหา ให้เปิดเซิร์ฟเวอร์ที่โดเมนของมันเองแล้วให้หน้าเว็บเรียกตรง

### สำรองข้อมูล

ฐานข้อมูลคือไฟล์ `data/e-kratong.db` (มีไฟล์ `-wal` และ `-shm` คู่กันขณะเซิร์ฟเวอร์ทำงาน) ให้หยุดเซิร์ฟเวอร์ก่อนคัดลอก หรือใช้ `sqlite3 data/e-kratong.db ".backup backup.db"`

### ถ้าคนเยอะกว่าที่เครื่องเดียวรับไหว

เซิร์ฟเวอร์ใช้โปรเซสเดียวเขียน SQLite และไฟล์เหตุการณ์ หากการอ่านจากผู้ชมทำให้เครื่องรับภาระมาก ให้ nginx หรือ CDN ส่ง `/log/` ตามตัวอย่างด้านบน แล้ววัดผลด้วยจำนวนผู้ชมและอัตราการลอยที่คาดในงานจริง

## API

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| `GET` | `/log/head.json` | ความคืบหน้าล่าสุด: ไฟล์ checkpoint และ segment ล่าสุด, `count`, `online`, `pledges`, `momentAt` |
| `GET` | `/log/cp-…json`, `/log/seg-…json` | สายน้ำทั้งหมด ณ จุดตรวจ / การเปลี่ยนแปลงรายวินาที (ไม่เปลี่ยนเนื้อหา แคชได้ตลอดกาล) |
| `POST` | `/api/krathongs` | ลอยกระทง `{ t, w, n, p }` ต้องมี header `X-Client-Token` |
| `DELETE` | `/api/krathongs/:k` | เก็บกระทงของตัวเอง หรือผู้ดูแลใช้ `X-Admin-Token` |
| `POST` | `/api/krathongs/:k/bless` | ส่งพร ตอบ `{ b }` จำนวนพรล่าสุด |
| `POST` | `/api/krathongs/:k/report` | แจ้งว่าไม่เหมาะสม |
| `POST` | `/api/moment` | (ผู้ดูแล) เริ่มนับถอยหลังปล่อยโคมพร้อมกัน `{ inSec }` 5–120 วินาที |
| `GET` | `/api/config` | ลิงก์สำหรับ QR และเวลาปล่อยโคม |
| `GET` | `/api/me` | id ย่อของฉัน, คำมั่นของฉัน, เป็นผู้ดูแลหรือไม่ |
| `PUT` | `/api/pledges` | บันทึกคำมั่น `{ pledges: [...] }` |
| `GET` | `/healthz` | สถานะเซิร์ฟเวอร์ |

`t` คือแบบกระทง: `suchada` `pratheep` `naga` `saphao` `lantern`
